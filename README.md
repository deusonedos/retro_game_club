# Retro Game Club

Telegram Mini App: каталог казуальных ретро-игр с недельными турнирами и PRO-подпиской.

**Боевой адрес:** https://deusonedos.github.io/retro_game_club/

- Продуктовый бриф — [RETRO CLUB.md](RETRO%20CLUB.md)
- Решения по открытым вопросам — [DECISIONS.md](DECISIONS.md)

## Запуск

```bash
npm install
npm run dev
```

Открывается на `http://localhost:5173`. Вне Telegram приложение работает в дев-режиме: подставляется тестовый пользователь, в профиле доступна кнопка сброса локальных данных, на пейволле — включение PRO без оплаты.

```bash
npm test     # логика гексагональной сетки Bubble Blast
npm run build
```

## Деплой

Автоматический: пуш в `main` → [workflow](.github/workflows/deploy.yml) прогоняет `npm test`, собирает и публикует на GitHub Pages. Тесты стоят до сборки, поэтому сломанная геометрия сетки или съехавшие границы сезона в прод не уедут.

Настраивать ничего не нужно, Pages уже включён с источником GitHub Actions.

Репозиторий публичный, поэтому **секретов в нём быть не должно**: токен бота, service-key Supabase и ключи платёжки живут в переменных окружения на сервере. Публичный anon-ключ Supabase во фронтенде — нормально, он для этого и предназначен, но только при включённой RLS на каждой таблице.

## Проверка внутри Telegram

`telegram-web-app.js` требует https, поэтому нужен туннель:

```bash
cloudflared tunnel --url http://localhost:5173
```

Полученный https-адрес прописывается боту через @BotFather → Bot Settings → Menu Button.

## Дизайн-система

«Неоновая ретро-аркада» — палитра, свечения и объёмные кнопки взяты из референса [bubble-blast.html](bubble-blast.html). Все токены объявлены в `:root` в [styles.css](src/styles.css); отдельного конфига нет.

**Про шрифты.** `Press Start 2P` содержит только латиницу и цифры — кириллица в нём отваливается на запасной моноширинный. Поэтому:

- пиксельный шрифт — на числах, латинице и логотипах (счёт, ранги, `BUBBLE BLAST`, `PRO`, `GAME OVER`);
- русские заголовки и подписи кнопок — `Rubik 800` капсом с разрядкой.

Отсюда правило: **`title` игры в реестре обязан быть на латинице**, всё русское — в `tagline`.

Акцент задаётся парой CSS-переменных `--accent` / `--accent-glow`, которые экраны выставляют инлайном из полей игры. Свой цвет у игры — свои свечения на карточке и в шапке.

## Структура

```
src/
  telegram/webapp.ts     единственное место, знающее про Telegram SDK
  api/                   контракт бэкенда + мок на localStorage
    types.ts             ApiClient — интерфейс, который заменит Supabase
    config.ts            продуктовые константы (лимиты, сезоны, цены)
    mockClient.ts        реализация для разработки
  games/
    types.ts             GameDefinition — контракт игры
    registry.ts          каталог: новая игра = одна запись здесь
    bubble-blast/
      grid.ts            чистая логика гекс-сетки (покрыта тестами)
      engine.ts          canvas, физика, рендер
  screens/               Игры / Рейтинг / Профиль / игровой экран
  state/AppState.tsx     профиль и глобальный пейволл
```

### Добавить игру

1. Модуль с функцией `mount(canvas, hooks): GameHandle`.
2. Запись в `GAMES` в [registry.ts](src/games/registry.ts).

Попытки, отправка очков, рейтинг и пейволл подхватываются автоматически — оболочка не меняется.

### Заменить мок на бэкенд

Реализовать `ApiClient` из [api/types.ts](src/api/types.ts) и переключить экспорт в [api/index.ts](src/api/index.ts). Экраны не трогаются.

## Что не сделано

- Бэкенд: всё живёт в localStorage. Счёт и попытки правятся из консоли — см. DECISIONS.md, вопрос A.
- Проверка `initData` по HMAC (вопрос D).
- Интеграция Tribute: `startProCheckout()` возвращает заглушку вместо `webappPaymentUrl`.
- Разовые покупки: кнопки в профиле неактивны.
- Реклама: сознательно отложена (DECISIONS.md, вопрос 2).
- Игры №2 и №3: слоты «Скоро» в каталоге.
