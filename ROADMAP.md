# План работ

**Текущая цель: игра и рейтинг. Монетизация отложена.**

Порядок подчинён одному принципу: сигнал о retention должен прийти раньше, чем построена платёжка и закуплен трафик. Экономика подписки, призового фонда и контент-плана из [DECISIONS.md](DECISIONS.md) целиком опирается на D7. Если игроки не возвращаются, турнир этого не исправит, а платный трафик просто вынесет деньги в трубу.

Отсюда форма плана: инфраструктура → бэкенд → рейтинг → удержание → **ворота** → рост → деньги.

### Стек

| Что | Зачем |
|---|---|
| GitHub + GitHub Pages | Репозиторий и хостинг. Пуш в `main` → тесты → сборка → публикация |
| Supabase (Франкфурт) | Общее состояние: пользователи, попытки, раунды, рейтинг |

Репозиторий публичный. **Ни одного секрета в нём:** токен бота, service-key Supabase и ключи платёжки живут только в переменных окружения на сервере. Публичный anon-ключ во фронтенде допустим, но **исключительно при включённой RLS на каждой таблице**.

# Фаза 1 · Бэкенд

Мок на localStorage заменяется реальным хранилищем. Реализуется интерфейс `ApiClient` из [api/types.ts](src/api/types.ts) — экраны не трогаются.

### Схема

```
users         telegram_id PK, username, first_name,
              first_seen_at, last_seen_at, beta_offer_accepted, coins
entitlements  id, user_id, source ('beta'|'admin'|'tribute'|'promo'),
              starts_at, ends_at, revoked_at, granted_by, external_id, note
attempts      user_id, game_id, day date, used     PK(user_id, game_id, day)
rounds        id uuid PK, user_id, game_id, started_at, finished_at,
              score, status ('active'|'finished'|'abandoned'), counted bool
seasons       id, starts_at, ends_at, prize_fund, prize_places, status
events        user_id, name, props jsonb, created_at
```

Двух таблиц намеренно нет:

- **Очков.** Рейтинг — агрегат `sum(score)` по `rounds` за окно сезона. Нечему разъезжаться с источником.
- **Статуса подписки.** `tier` выводится из `entitlements` (решение 9 в DECISIONS.md). Иначе ручное переключение из админки и вебхук платёжки перетирают друг друга, а бета-пользователей потом не найти.

### Раунд как транзакция

Это же и античит. Дешевле заложить сразу, чем переделывать под живыми деньгами.

1. Проверка `initData` по HMAC → выдача короткоживущего JWT. **Одна Edge Function на сессию.**
2. Старт раунда: атомарное списание попытки → запись `rounds` со статусом `active` → возврат `roundId`.
3. Закрытие: раунд обязан быть `active` и принадлежать этому пользователю; проверка минимальной длительности и потолка очков в секунду.

Шаги 2–3 — функции внутри Postgres, вызываемые по JWT. Это принципиально: **так расход Edge Functions падает с ~600 тыс. в месяц до ~30 тыс.**, и бесплатного тарифа хватает с двадцатикратным запасом.

- [ ] Миграции **файлами в репозитории**, применяются вторым шагом. Проект Supabase становится расходником: потеряется — воссоздаётся за минуты.
- [ ] RLS явно в каждой миграции плюс политики. Триггер авто-RLS включён как второй контур.
- [ ] Логирование событий: `app_open`, `round_start`, `round_finish`, `paywall_view`. **Без этого нечем измерить D1/D7**, а на них держится весь план.
- [ ] Проверка админа переезжает на сервер, из публичного конфига убирается.
- [ ] Переключить `api/index.ts`, мок оставить для локальной разработки.

**Готово, когда** прогресс переживает переустановку Telegram и в базе видно, кто вернулся назавтра.

# Фаза 3 · Удержание

Самая недооценённая фаза. **В Mini Apps уведомления бота — главный рычаг возврата, и стоят они почти ничего.**

- [ ] Бот-бэкенд: Edge Function на вебхук + расписание
- [ ] «Сезон кончается через 12 часов, ты на 8-м месте» — за сутки до закрытия
- [ ] «Тебя обошли, ты выпал из топ-3» — точечно, не чаще раза в день
- [ ] «Попытки обновились» — только тем, кто вчера упёрся в лимит
- [ ] Итоги сезона в воскресенье вечером

Правило: не больше одного сообщения в день на игрока и обязательная отписка. Пережмём — получим блокировки бота вместо возвратов.

# Фаза 5 · Открытая бета и ворота

100–1000 человек. PRO выдаётся всем бесплатно, проверяется полный цикл с турниром.

Замер: D1, D7, длина сессии, раундов в день, доля упирающихся в 7 попыток, глубина просмотра рейтинга.

### Ворота

| Сигнал | Что делать |
|---|---|
| D7 ≥ 15% | Идём в рост и деньги |
| D7 8–15% | Чиним core loop, повторяем |
| D7 < 8% | Игра не держит. Ни платёжку, ни трафик не строить — менять игру №1 |

Отдельно: если почти никто не упирается в лимит попыток, paywall давить не будет — лимит правим **до** запуска платежей (вопрос B в DECISIONS.md).

# Фаза 6 · Рост

Порядок здесь важнее содержания. **Виральность до платного трафика** — иначе закупка льёт воду в дырявое ведро.

### 6.1 Виральные механики — сначала

Самое дешёвое, потому что мы уже внутри мессенджера, где шаринг нативен.

- [ ] Шаринг результата в чат: «Я набрал 18 420 в Bubble Blast» + кнопка открытия
- [ ] Реферальная программа: привёл друга — оба получают попытки или дни PRO
- [ ] Челлендж другу — прямой вызов в личке

Метрика: **K-фактор**. Сколько новых игроков приводит один существующий. Ниже 0.3 — виральность не работает, чинить механику. Выше 0.7 — можно расти почти без денег.

### 6.2 Бесплатные каналы

- [ ] Каталоги Telegram Mini Apps — попадание в подборки
- [ ] Посев в тематических чатах и сообществах
- [ ] Кросс-промо с другими Mini Apps: обмен аудиторией без денег

### 6.3 Платный трафик — только последним

Запускать, **когда известны D7 и K-фактор**. Без них невозможно посчитать, сколько можно платить за игрока.

- [ ] Закуп постов в тематических Telegram-каналах — начать с малых бюджетов на 3–5 каналах, замерить стоимость привёденного игрока по каждому
- [ ] TikTok — короткие ролики геймплея. Инструменты уже есть в рабочем окружении
- [ ] Официальная реклама Telegram Ads — самый дорогой вход, имеет смысл только при доказанной экономике

Правило: **новый канал открывается только после того, как предыдущий показал сходящуюся экономику.** Иначе бюджет размажется, и не будет понятно, что сработало.
