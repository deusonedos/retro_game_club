# План работ

**Текущая цель: игра и рейтинг. Монетизация отложена.**

Порядок подчинён одному принципу: сигнал о retention должен прийти раньше, чем построена платёжка. Экономика PRO-подписки, призового фонда и контент-плана из [DECISIONS.md](DECISIONS.md) целиком опирается на D7. Если игроки не возвращаются, турнир этого не исправит — и все работы по деньгам окажутся выброшенными.

Отсюда форма плана: инфраструктура → бэкенд → сезоны и рейтинг → прогон с замером → **ворота** → и только потом деньги, призы, каталог.

### Что даёт отказ от денег на этом этапе

Отпадают Tribute, вебхуки, состояния подписки, продления и отмены. **PRO становится флагом в базе и выдаётся всем** — рейтинг открыт для каждого, кто зашёл. Пейволл и его вёрстка остаются в коде выключенными.

Остаётся раунд как транзакция (`roundId`): не ради защиты денег, а ради того, чтобы цифры retention были правдой, а таблица лидеров не правилась из консоли. Сложную эвристику правдоподобности при этом можно отложить.

### Стек

| Что | Зачем |
|---|---|
| GitHub + GitHub Pages | Репозиторий и хостинг статики в одном месте. Mini App — это веб-страница, Telegram открывает её по https |
| Supabase | Общее состояние. Рейтинг невозможен на localStorage: телефоны не видят друг друга |

Репозиторий **публичный**: Pages на приватном требует платного тарифа, а скрывать во фронтенде нечего — он и так целиком уезжает в браузер игрока. Отсюда правило: **ни одного секрета в репозитории.** Токен бота, service-key Supabase и ключи платёжки живут только в переменных окружения на сервере. Во фронтенде допустим лишь публичный anon-ключ.

## Фаза 1 · Бэкенд-минимум

Мок на localStorage заменяется реальным хранилищем. Реализуется интерфейс `ApiClient` из [api/types.ts](src/api/types.ts) — экраны не трогаются.

### Схема (Supabase)

```
users         telegram_id PK, username, first_name,
              first_seen_at, last_seen_at, beta_offer_accepted, coins
entitlements  id, user_id, source ('beta'|'admin'|'tribute'|'promo'),
              starts_at, ends_at, revoked_at, granted_by, external_id, note
attempts      user_id, game_id, day date, used     PK(user_id, game_id, day)
rounds        id uuid PK, user_id, game_id, started_at, finished_at,
              score, status ('active'|'finished'|'abandoned'), counted bool
seasons       id, starts_at, ends_at, prize_fund, prize_places, status
events        user_id, name, props jsonb, created_at
```

Двух таблиц намеренно нет:

- **Очков.** Рейтинг — агрегат `sum(score)` по `rounds` за окно сезона. Нечему разъезжаться с источником.
- **Статуса подписки.** `tier` выводится из `entitlements`, а не хранится (решение 9 в DECISIONS.md). Иначе ручное переключение из админки и вебхук платёжки перетирают друг друга, а бета-пользователей потом не найти.

### Раунд как транзакция

Это же и есть античит (вопрос A в DECISIONS.md). Дешевле заложить сразу, чем переделывать под живыми деньгами.

1. `POST /round/start` → проверка `initData` по HMAC → атомарное списание попытки → создание `rounds` со статусом `active` → возврат `roundId`.
2. Клиент играет.
3. `POST /round/finish {roundId, score}` → раунд обязан быть `active` и принадлежать этому пользователю → проверка правдоподобности (минимальная длительность, потолок очков в секунду) → `finished`.

Свойства: попытка не списывается дважды, счёт нельзя отправить без раунда, один раунд закрывается один раз, «миллион очков за 2 секунды» отсекается.

- [ ] Проверка `initData` по HMAC в Edge Function (вопрос D). Все записи — только через функции, RLS запрещает клиенту писать напрямую.
- [ ] Списание попыток, `roundId`, приём очков.
- [ ] Логирование событий (`app_open`, `round_start`, `round_finish`, `paywall_view`) — **без этого нечем измерить D1/D7**, а весь план построен вокруг этой цифры.
- [ ] Переключить `api/index.ts` на новую реализацию, мок оставить для локальной разработки.
- [ ] **Админка на сервере.** Экран уже готов; на бэкенде нужны проверка `ADMIN_IDS` по telegram id (серверная — клиентскому флагу доверять нельзя), список пользователей и ручная выдача с источником `admin`.

**Готово, когда** прогресс переживает переустановку Telegram и в базе видно, кто вернулся на следующий день.

- [ ] Уведомления от бота — в TMA это главный рычаг возврата и почти бесплатный: «сезон кончается через 12 часов, ты на 8-м месте».
- [ ] Замер: D1, D7, длина сессии, число раундов в день, доля упирающихся в 7 попыток, глубина просмотра рейтинга.

### Ворота

| Сигнал | Что делать |
|---|---|
| D7 ≥ 15% | Идём в фазу 4 |
| D7 8–15% | Чиним core loop Bubble Blast, повторяем тест |
| D7 < 8% | Игра не держит. Платёжку не строить, менять игру №1 |

Отдельно смотрим, упираются ли в лимит попыток. Если почти никто не упирается — paywall не будет давить, и лимит надо пересматривать (вопрос B) **до** запуска платежей, а не после.
